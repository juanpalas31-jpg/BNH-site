# Spider Eggs

Spider Eggs are dormant lineage packages. They preserve enough structural DNA and documentation to reconstruct a compatible Spider organism without embedding customer data, raw human DNA, private identities or secret keys in the public repository.

## Core sequence
dormant -> integrity verification -> lineage verification -> private claim verification -> legacy capsule -> recipient consent -> hatch

Hatching is never automatic. A recipient can refuse. Guardian custody and financial/legal succession remain separate from technical verification.

## Reunion
Sibling eggs may recognize a common ancestral lineage, but reunion is only a candidate operation. Authentication, compatibility review and explicit authorization are required before any future merge. Customer data is never inherited or merged by lineage.

## Long-term rule
Prefer documented, portable, self-describing formats over maximum compression. Integrity, recoverability and comprehensibility matter more than file size.
